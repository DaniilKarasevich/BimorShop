# BimorShop — глоссарий ключевых терминов

## Аккаунт (Account)
Основная сущность пользователя в системе. Содержит личную информацию (никнейм, имя, фамилию, email, телефон) и может быть как покупателем, так и продавцом.

## Продукт (Product)
Товар, доступный для покупки в магазине. Содержит информацию о названии, цене, категории и может быть связан с аккаунтом-продавцом.

## Заказ (Order)
Транзакция между покупателем и магазином, содержащая один или несколько продуктов. Может быть как обычным заказом, так и избранным.

## Избранное (Favorites)
Механизм сохранения интересных товаров для последующего просмотра. Реализован через специальный тип заказа с флагом `favorite = true`.

## Категория (Category)
Классификатор товаров по типам или темам. Используется для фильтрации и организации каталога.

## REST API
Архитектурный стиль взаимодействия компонентов системы через HTTP-методы (GET, POST, PUT, DELETE). Используется для связи фронтенда и бэкенда.

## Spring Boot
Фреймворк Java для создания standalone веб-приложений с минимальной конфигурацией. Основа бэкенд-части проекта.

## JPA (Jakarta Persistence API)
Спецификация Java для работы с реляционными базами данных через ORM (Object-Relational Mapping). Используется для маппинга сущностей на таблицы БД.

## Hibernate
Реализация JPA, используемая в проекте для управления персистентностью данных и выполнения запросов к базе данных.

## Entity (Сущность)
Класс Java, помеченный аннотацией `@Entity`, представляющий таблицу в базе данных (например, Account, Product, Order).

## Repository (Репозиторий)
Интерфейс Spring Data, предоставляющий CRUD-операции для работы с сущностями. Расширяет JpaRepository для доступа к данным.

## Service (Сервис)
Слой бизнес-логики приложения. Содержит основную логику обработки данных, валидацию и взаимодействие между контроллерами и репозиториями.

## Controller (Контроллер)
Компонент Spring MVC, обрабатывающий HTTP-запросы и возвращающий HTTP-ответы. Определяет endpoints API.

## DTO (Data Transfer Object)
Объект для передачи данных между слоями приложения. В текущей реализации используется непосредственно Entity, но рекомендуется выделение отдельных DTO.

## Bean Validation
Механизм валидации данных на уровне модели с использованием аннотаций (`@NotBlank`, `@Email`, `@Size`, etc.).

## JSON (JavaScript Object Notation)
Формат обмена данными, используемый в API для сериализации и десериализации объектов Java.

## CORS (Cross-Origin Resource Sharing)
Механизм безопасности браузеров, контролирующий кросс-доменные запросы. Настроен для доступа с любых источников.

## Swagger/OpenAPI
Инструмент для документирования и тестирования REST API. Предоставляет интерактивную документацию endpoints.

## Lombok
Библиотека Java, генерирующая boilerplate-код (геттеры, сеттеры, конструкторы) через аннотации.

## PostgreSQL
Реляционная система управления базами данных, используемая в проекте для хранения данных.

## Entity Relationships (Связи сущностей)
Определения отношений между таблицами в БД:
- **OneToMany**: Один аккаунт → много заказов
- **ManyToOne**: Многие продукты → один аккаунт (продавец)
- **ManyToMany**: Многие заказы ↔ многие продукты

## Cascade Operations (Каскадные операции)
Автоматическое распространение операций с родительской сущностью на связанные дочерние (например, удаление аккаунта → удаление его заказов).

## Fetch Type (Тип загрузки)
Стратегия загрузки связанных данных:
- **EAGER**: Немедленная загрузка
- **LAZY**: Отложенная загрузка при обращении

## JPQL (Java Persistence Query Language)
Язык запросов JPA для работы с сущностями вместо таблиц БД. Используется для сложных запросов.

## Native Query
Нативный SQL-запрос, используемый для специфических операций, не поддерживаемых JPQL.

## Transaction (Транзакция)
Атомарная операция работы с БД. Управляется через аннотацию `@Transactional` в сервисном слое.

## ORM (Object-Relational Mapping)
Технология преобразования объектов Java в записи базы данных и обратно.

## MVC (Model-View-Controller)
Архитектурный паттерн, разделяющий приложение на три компонента:
- **Model**: Сущности и бизнес-логика
- **View**: Представление (в данном случае JSON API)
- **Controller**: Обработка запросов

## CRUD (Create, Read, Update, Delete)
Базовые операции работы с данными, реализованные во всех сущностях системы.

## Authentication (Аутентификация)
Процесс проверки учетных данных пользователя. В текущей реализации — простая проверка email/пароля.

## Authorization (Авторизация)
Определение прав доступа пользователя к ресурсам системы. Требует доработки (планируется Spring Security + JWT).

## Validation Exception (Исключение валидации)
Исключение, возникающее при некорректных входных данных с HTTP статусом 400 (Bad Request).

## ResourceNotFoundException
Кастомное исключение для случаев, когда запрашиваемый ресурс не найден (HTTP 404).

## ResponseStatusException
Исключение Spring для возврата специфичных HTTP статусов с сообщениями об ошибках.

## API Endpoint
URL-адрес для доступа к конкретному ресурсу или операции API (например, `/api/products`).

## HTTP Methods (Методы HTTP)
- **GET**: Получение данных
- **POST**: Создание нового ресурса
- **PUT**: Полное обновление ресурса
- **DELETE**: Удаление ресурса
- **PATCH**: Частичное обновление ресурса

## Status Codes (Коды состояния HTTP)
- **200 OK**: Успешный запрос
- **201 Created**: Ресурс создан
- **400 Bad Request**: Некорректный запрос
- **404 Not Found**: Ресурс не найден
- **500 Internal Server Error**: Ошибка сервера

## Business Logic Layer (Слой бизнес-логики)
Центральный слой приложения, содержащий правила обработки данных, валидацию и координацию между компонентами.

## Data Access Layer (Слой доступа к данным)
Слой, отвечающий за взаимодействие с базой данных через репозитории.

## Presentation Layer (Слой представления)
Слой, предоставляющий интерфейс для внешних клиентов (REST API).

## Project Lombok Annotations (Аннотации Lombok)
- `@Getter`/`@Setter`: Генерация геттеров/сеттеров
- `@NoArgsConstructor`: Конструктор без параметров
- `@AllArgsConstructor`: Конструктор со всеми параметрами
- `@Builder`: Реализация паттерна Builder

## Spring Annotations (Аннотации Spring)
- `@SpringBootApplication`: Главный класс приложения
- `@RestController`: REST контроллер
- `@Service`: Бизнес-сервис
- `@Repository`: Репозиторий доступа к данным
- `@Entity`: Сущность JPA
- `@Component`: Общий компонент Spring

## JPA Annotations (Аннотации JPA)
- `@Id`: Первичный ключ
- `@GeneratedValue`: Стратегия генерации ID
- `@Column`: Настройка колонки БД
- `@OneToMany`/`@ManyToOne`/`@ManyToMany`: Определение связей
- `@Transient`: Поле, не сохраняемое в БД

## JSON Annotations (Аннотации JSON)
- `@JsonIgnore`: Игнорирование поля при сериализации
- `@JsonProperty`: Кастомное имя поля JSON
- `@JsonInclude`: Условия включения поля
- `@JsonManagedReference`/`@JsonBackReference`: Управление циклическими ссылками

## Bean Validation Annotations (Аннотации валидации)
- `@NotBlank`: Непустая строка
- `@Email`: Валидный email
- `@Size`: Ограничение длины строки
- `@Positive`: Положительное число

## Constructor Injection (Внедрение через конструктор)
Паттерн внедрения зависимостей Spring, используемый через `@AllArgsConstructor` Lombok.

## Layered Architecture (Многослойная архитектура)
Архитектура приложения с четким разделением ответственности между слоями (Controller → Service → Repository → Model).

## API Documentation (Документация API)
Автоматически генерируемая документация через Swagger UI, доступная по адресу `/swagger-ui.html`.

## Build Tool (Инструмент сборки)
Maven или Gradle для управления зависимостями и сборки проекта. В данном случае — Maven.

## Dependency Injection (Внедрение зависимостей)
Механизм Spring для управления зависимостями между компонентами приложения.

## Inversion of Control (Инверсия управления)
Принцип, при котором управление объектами передается контейнеру Spring.

## Application Context (Контекст приложения)
Контейнер Spring, управляющий жизненным циклом бинов и их зависимостями.

## Bean
Объект, управляемый Spring контейнером. Создается, настраивается и ассемблируется контейнером.

## Profile (Профиль)
Набор конфигураций для разных сред выполнения (dev, test, prod).

## Configuration Properties (Конфигурационные свойства)
Настройки приложения, загружаемые из `application.properties` или `application.yml`.

## Actuator
Spring Boot модуль для мониторинга и управления приложением (требует подключения).

## Unit Testing (Модульное тестирование)
Тестирование отдельных компонентов приложения (сервисов, контроллеров) изолированно.

## Integration Testing (Интеграционное тестирование)
Тестирование взаимодействия между компонентами и с внешними системами (БД, API).

## Mocking (Мокирование)
Замена реальных зависимостей тестовыми двойниками в unit-тестах.

## Test Coverage (Покрытие тестами)
Метрика, показывающая процент кода, покрытого тестами.

## CI/CD (Continuous Integration/Continuous Deployment)
Автоматизация процессов сборки, тестирования и развертывания приложения.

## Docker
Платформа для контейнеризации приложений, позволяющая упаковать приложение со всеми зависимостями.

## Kubernetes
Система оркестрации контейнеров для автоматизации развертывания, масштабирования и управления приложениями.

## Microservices (Микросервисы)
Архитектурный стиль, при котором приложение состоит из небольших независимых сервисов. В данном проекте — монолитная архитектура.

## Monolithic Architecture (Монолитная архитектура)
Архитектура, при которой все компоненты приложения развертываются вместе как единое целое.

## Scalability (Масштабируемость)
Способность системы обрабатывать возрастающую нагрузку. Может быть вертикальной (увеличение ресурсов) или горизонтальной (добавление инстансов).

## Performance (Производительность)
Характеристики системы по скорости обработки запросов и эффективности использования ресурсов.

## Security (Безопасность)
Меры защиты приложения от несанкционированного доступа, атак и утечек данных.

## Logging (Логирование)
Запись событий приложения для диагностики проблем и аудита.

## Monitoring (Мониторинг)
Отслеживание состояния и производительности приложения в реальном времени.

## Analytics (Аналитика)
Сбор и анализ данных о работе приложения для принятия бизнес-решений.

## Frontend-Backend Integration (Интеграция фронтенда и бэкенда)
Взаимодействие клиентской части (HTML/CSS/JS) с серверной через REST API.

## Single Page Application (SPA)
Веб-приложение, загружающее одну HTML-страницу и динамически обновляющее контент. В данном случае — классическое многостраничное приложение.

## Responsive Design (Адаптивный дизайн)
Дизайн интерфейса, адаптирующийся под разные размеры экранов устройств.

## User Experience (UX)
Опыт пользователя при взаимодействии с приложением, включая удобство, эффективность и удовлетворенность.

## User Interface (UI)
Визуальная часть приложения, с которой взаимодействует пользователь.

## State Management (Управление состоянием)
Управление состоянием данных в приложении, особенно важно в SPA.

## AJAX (Asynchronous JavaScript and XML)
Технология асинхронного обмена данными между браузером и сервером без перезагрузки страницы.

## Session Management (Управление сессиями)
Механизм поддержания состояния пользователя между запросами.

## Cache (Кэш)
Временное хранилище данных для ускорения доступа к часто используемым ресурсам.
