## Настройка тестового окружения
- **Java**: 17+
- **Spring Boot**: 3.x
- **База данных**: PostgreSQL 14+ (или H2 для тестирования)
- **Maven**: 3.8+
- **Библиотеки**: 
  - Spring Boot Starter Web
  - Spring Boot Starter Data JPA

  - Springdoc OpenAPI
- **Фронтенд**: Современный браузер (Chrome 90+, Firefox 88+, Edge 90+)

## Категории тестирования

### 1. Функциональное тестирование API
#### 1.1 Управление аккаунтами
- Регистрация нового пользователя (`POST /api/accounts/register`)
- Вход в систему (`POST /api/accounts/login`)
- Получение списка аккаунтов (`GET /api/accounts`)
- Получение аккаунта по ID (`GET /api/accounts/{id}`)
- Обновление аккаунта (`PUT /api/accounts/{id}`)
- Удаление аккаунта (`DELETE /api/accounts/{id}`)
- Каскадное удаление (аккаунт → его заказы)

#### 1.2 Управление товарами
- Создание товара (`POST /api/products`)
- Получение списка товаров (`GET /api/products`)
- Фильтрация по категории (`GET /api/products?category=electronics`)
- Фильтрация по цене (`GET /api/products?price=100`)
- Получение товара по ID (`GET /api/products/{id}`)
- Обновление товара (`PUT /api/products/{id}`)
- Удаление товара (`DELETE /api/products/{id}`)
- Пакетное создание товаров (`POST /api/products/create-several-products`)

#### 1.3 Управление заказами
- Создание заказа (`POST /api/orders`)
- Получение всех заказов (`GET /api/orders`)
- Получение заказа по ID (`GET /api/orders/{id}`)
- Получение заказов пользователя (`GET /api/orders?accountId={id}`)
- Обновление заказа (`PUT /api/orders/{id}`)
- Удаление заказа (`DELETE /api/orders/{id}`)

#### 1.4 Функция избранного
- Добавление в избранное (`POST /api/orders/favorite?accountId={id}&productId={id}`)
- Получение избранного (`GET /api/orders/favorite/{accountId}`)
- Удаление из избранного (`DELETE /api/orders/favorite?accountId={id}&productId={id}`)

#### 1.5 Фильтрация заказов
- По категории товаров (JPQL) (`GET /api/orders/filter/by-category-jpql?category=electronics`)
- По цене товаров (Native Query) (`GET /api/orders/filter/by-price-native?price=100`)

#### 1.6 Валидация данных
- Валидация email (`@Email`)
- Валидация пароля (`@Size(min = 6)`)
- Валидация уникальности (email, phone, nickname)
- Валидация цен (`@Positive`, `@PositiveOrZero`)
- Валидация обязательных полей (`@NotBlank`, `@NotNull`)

### 2. Интеграционное тестирование
- Работа с PostgreSQL через JPA/Hibernate
- Связи между сущностями (OneToMany, ManyToOne, ManyToMany)
- Каскадные операции при удалении
- Транзакционность операций (`@Transactional`)
- JSON сериализация/десериализация с Jackson
- Обработка исключений через `@RestControllerAdvice`
- CORS настройки и работа с фронтендом

### 3. Нефункциональное тестирование
#### 3.1 Производительность
- Время отклика API (< 500 мс для основных операций)
- Обработка множества одновременных запросов
- Производительность при большом количестве данных
- Оптимизация запросов к БД

#### 3.2 Безопасность
- Валидация входных данных
- Защита от SQL-инъекций (параметризованные запросы через JPA)
- CORS настройки
- Отсутствие XSS уязвимостей (в текущей реализации)
- Защита паролей (требует внедрения Spring Security)

#### 3.3 Надежность
- Отказоустойчивость при ошибках БД
- Сохранение целостности данных
- Восстановление после сбоев
- Логирование критических операций

#### 3.4 Масштабируемость
- Возможность горизонтального масштабирования
- Производительность при увеличении нагрузки
- Оптимизация использования памяти

#### 3.5 Совместимость
- Работа с различными версиями Java
- Совместимость с разными версиями PostgreSQL
- Кросс-браузерная совместимость фронтенда
- Работа на разных ОС (Windows, Linux, macOS)

## Известные проблемы и риски

### Высокий приоритет:
1. **Безопасность паролей** - пароли хранятся в открытом виде
2. **Отсутствие аутентификации** - нет механизма авторизации (JWT/Sessions)
3. **XSS уязвимости** - некоторые места могут быть уязвимы

### Средний приоритет:
4. **Производительность поиска** - фильтрация на клиенте при большом количестве товаров
5. **Отсутствие пагинации** - все данные загружаются сразу
6. **Нет валидации на фронтенде** - только бэкенд валидация

### Низкий приоритет:
7. **Отсутствие кэширования** - частые запросы к БД
8. **Нет обработки изображений** - только ссылки на изображения
9. **Ограниченная фильтрация** - только по категории и цене

## Часто задаваемые вопросы (FAQ)

**Q: Как запустить тесты локально?**
A: `mvn test` или через IDE (запустить классы с аннотацией `@Test`)

**Q: Где найти отчеты о покрытии кода?**
A: После выполнения `mvn jacoco:report` в `target/site/jacoco/index.html`

**Q: Как проверить работоспособность API без Postman?**
A: Использовать Swagger UI по адресу `http://localhost:8080/swagger-ui.html`

**Q: Какие данные нужны для тестовой БД?**
A: Можно использовать встроенный скрипт `data.sql` или заполнить через API

**Q: Как сообщить об ошибке?**
A: Создать Issue в GitHub с шаблоном bug report
