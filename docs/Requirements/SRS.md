# 1 Введение

<a name="appointment"/>

## 1.1 Назначение
В этом документе описаны функциональные и нефункциональные требования к веб-приложению **BimorShop** — системе управления интернет-магазином для малого и среднего бизнеса. Документ предназначен для команды разработки, тестирования и заинтересованных сторон проекта.

<a name="business_requirements"/>

## 1.2 Бизнес-требования

<a name="initial_data"/>

### 1.2.1 Исходные данные
С развитием электронной коммерции владельцы малого бизнеса нуждаются в простых, но функциональных системах для управления своими онлайн-магазинами. Существующие решения часто слишком сложны или дороги для небольших предприятий.

<a name="business_opportunities"/>

### 1.2.2 Возможности бизнеса
Приложение позволит:
- Владельцам магазинов легко управлять товарами и заказами
- Покупателям удобно просматривать товары, создавать заказы и сохранять избранное
- Администраторам управлять пользователями, товарами и анализировать продажи
- Предоставить REST API для возможной интеграции с мобильными приложениями

<a name="project_boundary"/>

### 1.2.3 Границы проекта
**BimorShop** предоставляет следующие возможности:

**Покупатели могут:**
- Регистрироваться и входить в систему
- Просматривать каталог товаров с фильтрацией
- Создавать и управлять заказами
- Добавлять товары в избранное
- Управлять своим профилем

**Владельцы магазинов могут:**
- Управлять своим каталогом товаров (добавлять, редактировать, удалять)
- Просматривать и обрабатывать заказы
- Управлять информацией о магазине

**Администраторы могут:**
- Управлять всеми пользователями
- Просматривать аналитику по заказам
- Контролировать всю систему

**Анонимные пользователи могут:**
- Просматривать каталог товаров
- Видеть базовую информацию о товарах

<a name="analogues"/>

## 1.3 Аналоги
**Shopify**, **WooCommerce**, **Magento Community Edition**  
Преимущества **BimorShop**: 
- Простая архитектура и легкое развертывание
- Низкие требования к инфраструктуре
- Гибкая настройка под нужды конкретного бизнеса
- Открытая архитектура для кастомизации

<a name="user_requirements"/>

# 2 Требования пользователя

<a name="software_interfaces"/>

## 2.1 Программные интерфейсы
Приложение использует:
- **Backend**: Java 17+, Spring Boot 3.x
- **Frontend**: React/Angular/Vue.js (опционально, через REST API)
- **База данных**: PostgreSQL/MySQL через Spring Data JPA
- **Авторизация**: JWT (планируется к реализации)
- **Документация API**: Swagger/OpenAPI 3.0
- **Сборка**: Maven/Gradle
- **Контейнеризация**: Docker (опционально)

<a name="user_interface"/>

## 2.2 Интерфейс пользователя
Приложение предоставляет RESTful API со следующими основными endpoint'ами:

### Основные API endpoints:
- `POST /api/accounts/register` - Регистрация нового пользователя
- `POST /api/accounts/login` - Вход в систему
- `GET /api/products` - Получение списка товаров
- `GET /api/products/{id}` - Получение деталей товара
- `POST /api/orders` - Создание заказа
- `GET /api/orders/favorite/{accountId}` - Получение избранных товаров
- `POST /api/orders/favorite` - Добавление в избранное

### Web интерфейс (планируется):
- Главная страница с каталогом товаров
- Личный кабинет пользователя
- Панель управления для администраторов
- Корзина покупок и оформление заказа

|:---|:---|:---|

<a name="application_audience"/>

### 2.3.2 Аудитория приложения

<a name="target_audience"/>

#### 2.3.2.1 Целевая аудитория
- Владельцы малого и среднего бизнеса, желающие создать интернет-магазин
- Покупатели, ищущие товары в нишевых магазинах
- Разработчики, которым нужна готовая основа для e-commerce проектов

<a name="collateral_audience"/>

#### 2.3.2.2 Побочная аудитория
- Студенты, изучающие Spring Boot и разработку e-commerce систем
- IT-консультанты, внедряющие готовые решения для клиентов
- Маркетологи, анализирующие данные о покупках

<a name="assumptions_and_dependencies"/>

## 2.4 Предположения и зависимости
1. Наличие JDK 17+ для запуска приложения
2. Доступ к реляционной БД (PostgreSQL/MySQL)
3. Интернет-соединение для работы веб-интерфейса
4. Совместимость с современными браузерами (для веб-интерфейса)
5. Возможность расширения функционала (платежные системы, доставка, аналитика)

#### 3.1.1.3 Управление профилем пользователя

| Редактирование товара | Обновление информации о товаре | `PUT /api/products/{id}` |

<a name="filtering_and_search"/>

#### 3.1.1.7 Фильтрация и поиск
| Функция | Требования | Метод API |
|:---|:---|:---|
| Фильтрация товаров | По категории и/или цене | `GET /api/products?category=...&price=...` |
| Фильтрация заказов по категории | Заказы, содержащие товары определенной категории (JPQL) | `GET /api/orders/filter/by-category-jpql?category=...` |
| Фильтрация заказов по цене | Заказы, содержащие товары определенной цены (Native Query) | `GET /api/orders/filter/by-price-native?price=...` |

<a name="restrictions_and_exclusions"/>

### 3.1.2 Ограничения и исключения
1. **Требуется авторизация** для создания заказов и управления избранным
2. **Уникальные поля**: email, телефон и nickname должны быть уникальными
3. **Минимальная длина пароля**: 6 символов
4. **Целостность данных**: удаление пользователя приводит к каскадному удалению его заказов
5. **Ограничения на размеры полей**:
   - Nickname: до 50 символов
   - Имя/Фамилия: до 100 символов
   - Название товара: до 255 символов
   - Категория: до 100 символов

<a name="non-functional_requirements"/>

## 3.2 Нефункциональные требования

<a name="quality_attributes"/>

### 3.2.1 Атрибуты качества

<a name="requirements_for_ease_of_use"/>

#### 3.2.1.1 Требования к удобству использования
1. **Интуитивный API**: RESTful дизайн с предсказуемыми endpoint'ами
2. **Полная документация**: Swagger UI для тестирования API
3. **Консистентность ответов**: Единый формат ответов для всех endpoint'ов
4. **Подробные сообщения об ошибках**: Четкие сообщения при валидационных ошибках

<a name="security_requirements"/>

#### 3.2.1.2 Требования к безопасности
1. **Валидация входных данных**: Использование Jakarta Bean Validation
2. **Защита от SQL-инъекций**: Использование параметризованных запросов через JPA
3. **Управление зависимостями**: Регулярное обновление зависимостей Maven
4. **CORS настройки**: Контролируемый доступ к API
5. **Защита паролей**: Планируется внедрение шифрования (BCrypt)

<a name="performance_requirements"/>

#### 3.2.1.3 Требования к производительности
1. **Время отклика API**: ≤ 500 мс для основных операций
2. **Поддержка нагрузки**: До 1000 одновременных пользователей
3. **Оптимизация запросов**: Использование LAZY/EAGER загрузки по необходимости
4. **Кэширование**: Возможность добавления Spring Cache для часто запрашиваемых данных
5. **Пагинация**: Поддержка постраничного вывода для списков

<a name="external_interfaces"/>

### 3.2.2 Внешние интерфейсы
1. **REST API**: JSON over HTTP/HTTPS
2. **База данных**: JDBC через Hibernate JPA
3. **Веб-интерфейс**: HTML/JavaScript (планируется)
4. **Интеграции**: Возможность интеграции с платежными системами и службами доставки

<a name="restrictions"/>

### 3.2.3 Ограничения
1. **Технологический стек**: Java Spring Boot, реляционная БД
2. **Масштабируемость**: Вертикальное масштабирование (одна БД, один сервер приложений)
3. **Мультитенантность**: Отсутствует в текущей версии
4. **Интернационализация**: Только русский/английский язык в сообщениях
5. **Мобильные приложения**: Только через REST API, нативных приложений нет

## Технические характеристики текущей реализации

### Архитектура:
- **Паттерн**: MVC (Model-View-Controller)
- **Слои**: Controller → Service → Repository → Model
- **ORM**: Jakarta Persistence API (JPA) с Hibernate

### База данных:
- **Схема**: 3 основные таблицы (accounts, products, orders) + связующая таблица (order_product)
- **Связи**: OneToMany, ManyToMany, ManyToOne
- **Миграции**: Не используются (автогенерация таблиц)

### Текущие особенности:
1. **Бизнес-логика в сервисах**: Вся основная логика реализована в сервисном слое
2. **Каскадные операции**: Удаление пользователя удаляет его заказы
3. **Транзакционность**: Использование `@Transactional` для операций изменения данных
4. **Валидация**: На уровне модели и контроллера
5. **Документация**: Swagger/OpenAPI для всех endpoint'ов

### Планируемые улучшения:
1. **Безопасность**: Добавление Spring Security и JWT
2. **Тестирование**: Unit и интеграционные тесты
3. **Логирование**: Централизованное логирование операций
4. **Мониторинг**: Spring Boot Actuator для метрик
5. **Кэширование**: Redis для часто запрашиваемых данных
